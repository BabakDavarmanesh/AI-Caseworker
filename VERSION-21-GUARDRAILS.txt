VERSION 21 - Scope guardrails (ported from ver8, hardened)

What it does
- Intercepts client utterances that are not intake answers:
  pr_chances (asking about PR / visa / approval chances),
  suggestion (asking for advice or recommendations),
  off_topic  (weather, jokes, unrelated questions).
- The utterance is NOT analyzed, NOT saved, and does NOT consume a follow-up.
- Clarification questions about the current question are explicitly allowed,
  so the Version 15 clarification follow-ups keep working.

Where
- js/app.js: guardrail core (messages en/fa/fr, regex fast path, LLM classifier,
  checkGuardrail). Inserted as a new block; no existing code changed.
- js/virtual-caseworker.js (Virtual Caseworker / Lisa): new "out_of_scope" turn.
  Lisa speaks the notice in the session language, then repeats the current prompt.
- js/client-intake.js (Client Intake): checked before analysis. Notice shown in the
  analysis panel; Play Question reads the notice + the same prompt (manual mode kept).

Fixes vs ver8
- Persian: LLM layer now runs for Persian questions (supports "؟" and Persian
  question words; JavaScript \b does not work with Persian letters).
- "What should I put/say/answer" no longer blocked by regex (it is a clarification).
- Fail-open: LLM errors or >4 s timeout never block the interview.
- Notice is not double-translated.

Not ported on purpose
- The extra GUARDRAIL rule inside the shared answer-analysis prompts (isOutOfScope).
  Nothing read that field, and in ver8 it consumed a follow-up and polluted the
  combined answer. Shared analysis prompts are left unchanged.

Kill switch
- Set GUARDRAILS_ENABLED = false in js/app.js to turn all guardrails off.
